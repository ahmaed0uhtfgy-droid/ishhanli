# اشحنلي — منصة نقل البضائع (MVP)

منصة ويب (Responsive، عربي/إنجليزي) تربط عملاء عندهم بضائع بسواقين نقل موثّقين في مصر، بالجنيه المصري، مع **Escrow** (المبلغ محجوز لحد تأكيد الاستلام) ولوحة أدمن كاملة.
الاسم في `public/js/i18n.js` (مفتاح `brand`) و`public/index.html`.

## المكوّنات (إيه بيعمل إيه)

| الخدمة | بتعمل إيه | تكلفة | بتتربط في |
|---|---|---|---|
| **Firebase Auth** | تسجيل الدخول | مجاني، بدون كارت | `public/js/config.js` + `FIREBASE_PROJECT_ID` |
| **Firebase Firestore** | **كل البيانات** (مستخدمين، طلبات، محفظة، نزاعات، شات، الصور) | مجاني على خطة Spark (بحدود يومية، تحت) | سر `FIREBASE_SERVICE_ACCOUNT` |
| **Cloudflare Pages** | استضافة الموقع + **السيرفر** (`functions/`: الصلاحيات والمنطق المالي) | مجاني | `wrangler.toml` |
| **Firebase Cloud Messaging** | إشعارات Push (طلب جديد، عرض سعر، تأكيد دفع…) | مجاني، اختياري | `config.js` (`vapidKey`) + نفس سر الخدمة |

```
المتصفح ──► Firebase Auth (دخول) ──► ID token
   └──► /api/*  (Cloudflare Pages Functions: صلاحيات + منطق مالي) ──► Firestore (بحساب خدمة)
```
المتصفح **مالوش وصول مباشر لـ Firestore** (القواعد في `firestore.rules` قافلة كل حاجة). كل قراءة وكتابة بتعدّي من السيرفر وبتتفلتر حسب دور المستخدم. السر الوحيد على السيرفر: `FIREBASE_SERVICE_ACCOUNT`.

### حدود الخطة المجانية (Spark) — مهم تعرفها
بحسب توثيق Firebase وقت كتابة النسخة دي: **1GiB تخزين، 50 ألف قراءة، 20 ألف كتابة، 20 ألف حذف في اليوم**، وبتتصفّر يومياً. لو خلصت، السيرفر بيرد `quota_exceeded` لحد التصفير.
- **تحديث ذكي (sync):** الشاشات المفتوحة بتسأل السيرفر كل شوية سؤال واحد رخيص (`sync`: قراءة واحدة، مشتركة بين كل الصفحات المفتوحة) عن "إيه اللي اتغيّر"، وما بتجيبش القوائم الكبيرة (طلبات، سحب، نزاعات…) إلا لما العدّاد بتاعها يتغيّر (أو كل 10 دورات كأمان). السيرفر بيزوّد العدّادات تلقائياً مع أي كتابة في المجموعات دي (في `firestore.js`). ده بيشيل معظم القراءات وقت ما مفيش حاجة بتحصل.
- الفواصل مضروبة ×2 (`POLL_SCALE` في `public/js/config.js`). لو رقّيت لـ **Blaze** (نفس الكوتا المجانية وبعدها بتدفع على الزيادة بدل ما يقف) ضَع `POLL_SCALE = 1` وبقى التحديث أسرع. الشات وصفحة الطلب لسه بيحدّثوا بالفاصل العادي (بيتعدّوا على sync لأن موقع السواق والعروض بتتغيّر باستمرار).
- كل مستخدم بيفتح طلب بيستهلك عشرات القراءات في الساعة، فالخطة المجانية مناسبة للتجربة وعدد قليل من المستخدمين المتزامنين. راقب **Firebase → Firestore → Usage**.
- الصور بتتضغط في المتصفح (~60-120KB) وبتتخزن كمستندات (حد المستند 1MiB).

## التشغيل خطوة بخطوة (من المتصفح، من غير ترمنال)

### 1) Firebase
1. [console.firebase.google.com](https://console.firebase.google.com) ← مشروعك.
2. **Authentication → Sign-in method →** فعّل **Email/Password**.
3. **Firestore Database → Create database →** اختار **Production mode** وأقرب منطقة متاحة ليك (**المنطقة ما بتتغيرش بعد كده**).
4. تبويب **Rules** ← امسح اللي موجود والصق محتوى ملف **`firestore.rules`** ← **Publish**. (ده بيقفل Firestore قدام أي متصفح، والسيرفر بيدخل بحساب الخدمة.)
5. **Project settings (⚙️) → Service accounts → Generate new private key** ← بينزل ملف JSON. **ده سر: ما تحطوش في GitHub ولا تبعته لحد.**
6. **Project settings → General → Your apps → Web** ← انسخ `firebaseConfig` إلى `public/js/config.js` (جاهز لمشروع `ishhanli`).

### 2) GitHub + Cloudflare Pages
1. ارفع محتوى المشروع على الريبو (الملفات نفسها في الروت، مش فولدر فوقها).
2. Cloudflare → **Workers & Pages → Create → Pages → Connect to Git** ← اختار الريبو.
3. **Build command: فاضي** — **Build output directory: `public`** ← **Save and Deploy**.
   > لازم تختار **Pages** (مش Workers). لو عندك Worker قديم بنفس الاسم امسحه.
4. بعد أول نشر: **Pages project → Settings → Variables and Secrets → Add** ← Type: **Secret** ← الاسم `FIREBASE_SERVICE_ACCOUNT` ← القيمة: **محتوى ملف الـ JSON كامل** (من `{` لـ `}`) ← Save.
5. **Deployments → ⋯ على آخر نشر → Retry deployment** (الأسرار بتتطبّق على النشرات الجديدة بس).

### 3) اربط Firebase بالدومين
Firebase → **Authentication → Settings → Authorized domains → Add domain** وأضف `ishhanli.pages.dev` (ودومينك المخصص لو عندك).

### 4) اتأكد إن كل حاجة متوصلة ✅
افتح: **`https://ishhanli.pages.dev/api/health`**
```json
{"db":true,"firestore":true,"push":true,"projectId":true,"ok":true}
```
`"ok": true` = حساب الخدمة موجود وFirestore بيرد ومعرّف Firebase تمام. (`push` مجرد إن الإشعارات مفعّلة من ناحية السيرفر، ومابيأثرش على `ok`.)

### 5) أول أدمن (من المتصفح)
1. افتح الموقع ← **سجّل** كعميل (إيميل + بيانات + صورة بطاقة).
2. Firebase → **Firestore Database → Data → مجموعة `users`** ← افتح المستند اللي اسمه = الـ UID بتاعك (بتلاقيه في **Authentication → Users**).
3. عدّل الحقلين (نوعهم string): **`role` = `admin`** و **`status` = `active`** ← Update.
4. اعمل خروج ودخول ← هتلاقي **لوحة التحكم**.

### 7) ظبط المنصة (لوحة التحكم → التسعير والإعدادات)
سعر الكيلومتر، الحد الأدنى، العمولة، معاملات الفئات والأحجام (**القيم الافتراضية أرقام تجريبية**)، وحساب InstaPay اللي بيظهر للعميل عند الدفع.

### 8) إشعارات Push — زي أوبر (اختياري، مجاني، ويُنصح بيه جداً)
من غيرها السواق بيشوف الطلب الجديد بس لو الموقع مفتوح. معاها بيوصله إشعار حتى لو الموقع مقفول.
1. Firebase → **Project settings → Cloud Messaging**: اتأكد إن **Firebase Cloud Messaging API (V1)** مفعّل.
2. نفس الصفحة → **Web Push certificates → Generate key pair** ← انسخ المفتاح إلى `public/js/config.js` (`vapidKey`).
3. حساب الخدمة (الخطوة 2.4) هو نفسه المستخدم للإشعارات — مفيش سر إضافي.
4. ارفع التعديل على GitHub (Cloudflare بينشر لوحده)، وبعدين من الموبايل: ادخل الموقع ← زر **«فعّل الإشعارات»** (والسواق: زر «متاح لاستقبال الطلبات» بيطلب الإذن تلقائياً).
5. لو عايز توقف الإشعارات من غير ما تمس باقي الموقع: متغير `PUSH_DISABLED` = `1`.
> **آيفون:** الإشعارات بتشتغل بس بعد **Share ← Add to Home Screen** (iOS 16.4+). أندرويد وكمبيوتر بيشتغلوا مباشرة.

### 9) جرّب دورة كاملة (مهم قبل أي مستخدم حقيقي)
حساب عميل + حساب سواق (بمتصفح/جهاز تاني) ← الأدمن يفعّلهم من «المستخدمين» ← طلب ← قبول ← دفع ← تأكيد من الأدمن ← الحالات الأربع (من موبايل حقيقي عشان الـ GPS) ← «وصلت شحنتي» ← راجع رصيد السواق (السعر − العمولة).

## قائمة التجربة (اختبر بنفسك قبل أي مستخدم حقيقي)
جهّز **4 حسابات** (استخدم متصفحات أو نوافذ Incognito مختلفة): أدمن (خطوة 6)، عميل، سواق بضاعة (ربع نقل أو نص نقل)، سواق ركاب (سيارة أو ميكروباص). فعّل الحسابات من «المستخدمين». الأحسن تجرّب **من موبايل حقيقي** خصوصاً الـ GPS والإشعارات.

| # | السيناريو | المتوقع |
|---|---|---|
| 1 | `/api/health` | `"ok": true` |
| 2 | عميل: طلب بضاعة (صور + دبوسين) ← سواق يقبل ← عميل يدفع (سكرين شوت) ← أدمن يأكد | السعر يظهر قبل الطلب، والحالات تتحدّث خلال ثواني |
| 3 | السواق: «في الطريق» ← «تم الاستلام» (صورة + من مكان بعيد) | من بعيد يترفض (`too_far`)، ومن قريب يتسجّل بالصورة |
| 4 | العميل: «وصلت شحنتي» | رصيد السواق = السعر − العمولة، والعميل يقيّم |
| 5 | عروض أسعار: طلب بـ «استقبل عروض» ← سواقين يقترحوا ← العميل يرتّب ويقبل | السعر الجديد يتثبّت والعمولة عليه |
| 6 | **دفع مقدم**: طلب بـ «ادفع مقدماً» ← أدمن يأكد ← السواق يقبل | الطلب يظهر للسواقين بعد التأكيد بس، والسواق يبدأ فوراً |
| 7 | **استرجاع**: طلب مدفوع مقدماً ← العميل «إلغاء واسترجاع» (قبل أي سواق) | يظهر في تاب «الاسترجاع» ← الأدمن «تم التحويل» ← العميل يتبلّغ |
| 8 | **انتهاء تلقائي**: طلب مدفوع ميعاده فات + المهلة (قلّل المهلة من الإعدادات لدقيقة للتجربة) | بيتلغي ويتسجّل استرجاع أول ما حد يفتح القوائم |
| 9 | **إلغاء برسوم**: سواق يقبل طلب مدفوع ← العميل يلغي | نافذة بالأرقام، ثم التقسيم (سواق/منصة/عميل) وتعويض في محفظة السواق |
| 10 | **اعتذار السواق**: سواق يقبل طلب مدفوع ← «اعتذر عن الطلب» | الطلب يرجع مفتوح لسواقين تانيين، والعميل يتبلّغ |
| 11 | **الشات**: بعد قبول سواق، الطرفين يتبادلوا رسايل | بتظهر عند الطرف التاني خلال ~6 ثواني + إشعار |
| 12 | **ركاب** (فعّلها من الإعدادات): حجز ميكروباص 10 ركاب ← دفع ← سواق ركاب يقبل ← إنهاء الرحلة | سواق البضاعة ما يقدرش يقبلها، ومفيش صور إجبارية، والزر «وصلت وجهتي» |
| 13 | **بلاغ**: من صفحة الطلب أو الشات | يظهر عند الأدمن ومعاه الشات |
| 14 | **طوارئ** (رحلة ركاب في الطريق): زر «طوارئ» ← «بلّغ الإدارة بموقعي» | الأدمن يستلم إشعار عاجل ويشوف الموقع |
| 15 | **الإشعارات** (بعد خطوة 8): سواق «متاح» وموقعه مقفول | إشعار «طلب جديد» يوصل حتى لو الصفحة مقفولة |

**لو لقيت مشكلة ابعتلي:** رقم السيناريو، الجهاز والمتصفح، لقطة شاشة، ونتيجة `/api/health`. ولو ظهر خطأ 500 شغّل `npx wrangler pages deployment tail --project-name=ishhanli` وابعت اللي يظهر.

## التشغيل على جهازك (اختياري، للمطورين)
```bash
npm install
# أنشئ ملف .dev.vars (مش بيترفع على Git) وحط فيه:  FIREBASE_SERVICE_ACCOUNT='{...محتوى JSON في سطر واحد...}'
npm run dev               # http://localhost:8788  (بيكلّم Firestore الحقيقي بتاعك)
npm test                  # الاختبارات (على Firestore وهمي، من غير إنترنت)
```

## التعديل والنشر بعد كده
- أي تعديل كود/تصميم/إعداد: عدّله على GitHub (أو ارفع الملف)، وCloudflare بينشر تلقائياً.
- متابعة الأخطاء لحظياً: Cloudflare → Pages project → **Deployments → View details → Functions → Real-time logs**.
- النسخ الاحتياطي: Firestore مابيعملش نسخ احتياطي تلقائي في الخطة المجانية على حد علمي — راجع توثيق Firebase للـ export (غالباً بيحتاج Blaze) قبل ما تشتغل بمستخدمين حقيقيين.
- الفهارس: الكود مكتوب بحيث ما يحتاجش أي **فهرس مركّب** في Firestore. لو ظهر في اللوج خطأ فيه «requires an index» ابعته للمطوّر.

## دومين خاص (اختياري)
Pages project → **Custom domains → Set up a domain**. بعدها: أضفه في Firebase Authorized domains، واستبدل `ishhanli.pages.dev` بدومينك في `public/index.html` (canonical + JSON-LD)، `robots.txt`، `sitemap.xml`، `llms.txt`، ثم `npm run deploy`.

## حل المشاكل

| العَرَض | السبب والحل |
|---|---|
| شريط أحمر «config.js …» أعلى الموقع | لسه ما عدّلتش `public/js/config.js` بقيم Firebase. |
| `/api/health` → `"db": false` | سر `FIREBASE_SERVICE_ACCOUNT` مش متضاف أو ما عملتش **Retry deployment** بعده (الخطوة 2.4–2.5). |
| `"firestore": false` | Firestore لسه ما اتعملش (الخطوة 1.3)، أو ملف الـ JSON بتاع مشروع تاني / مش كامل، أو حساب الخدمة مالوش صلاحية. شوف Real-time logs. |
| `"projectId": false` | `FIREBASE_PROJECT_ID` لسه `YOUR_...` في `wrangler.toml`. |
| خطأ `quota_exceeded` | خلصت الكوتا اليومية المجانية لـ Firestore (تتصفّر يومياً). رقّي لـ Blaze أو قلّل الاستخدام. |
| تسجيل الدخول ينجح لكن كل طلبات الـ API `invalid_token` | `FIREBASE_PROJECT_ID` مش نفس `projectId` اللي في `config.js`. |
| `auth/unauthorized-domain` | أضف الدومين في Firebase → Authorized domains. |
| `auth/operation-not-allowed` | Email/Password مش مفعّل في Firebase Authentication. |
| بعد التسجيل بيظهر «حسابك قيد المراجعة» | طبيعي: الأدمن لازم يفعّله. رقّي حسابك الأول (خطوة 6). |
| `db_error` أو 500 | افتح Real-time logs في Cloudflare وشوف الرسالة. |
| الصور مش بتظهر | راجع `firestore` في `/api/health` والـ logs. |
| طلب مدفوع مقدماً عدّى ميعاده ولسه «مفتوح» | الانتهاء بيتنفذ عند أول نشاط (فتح الطلب أو قائمة الطلبات) مش بجدول زمني. حدّث القائمة، أو راجع «مهلة الانتهاء» في الإعدادات (افتراضي 30 دقيقة بعد الميعاد). |
| العميل بيقول «دفعت وطلبي مش ظاهر للسواقين» | في الدفع المقدم الطلب بيظهر بعد ما الأدمن **يأكد الدفع** (تاب المدفوعات). |
| زر «استرجاع» / الاسترجاع مش نازل عند العميل | الاسترجاع يدوي: الأدمن بيحوّل على InstaPay من تاب «الاسترجاع» ويضغط «تم». |
| تعديلت `config.js` ولا تغيير | استنى النشر يخلص في Cloudflare وجرّب Ctrl+Shift+R. |

## اللي جاهز

| المجال | المُنفَّذ |
|---|---|
| العميل | **اختيار: قبول فوري أو استقبال عروض أسعار**، تسجيل + رفع بطاقة، طلب نقل بخريطة ودبوسين وبحث عن مكان، صور حمولة، **سعر تلقائي من السيرفر**، دفع InstaPay بإثبات، تتبع مباشر، «وصلت شحنتي»، تقييم، نزاع، إلغاء |
| السواق | **زر «متاح» + إشعار طلب جديد بصوت وعدّاد 30 ثانية (زي أوبر)، وقبول بالسعر المقترح أو اقتراح سعر**، تسجيل + رخصة/استمارة/صورة العربية/بطاقة (بمراجعة أدمن)، طلبات متاحة، قبول (أول سواق يكسب)، تحديث الحالة بـ**صورة إجبارية + فحص GPS**، بث الموقع، محفظة، طلب سحب |
| الأدمن | إحصائيات على كل الطلبات، مراجعة المستخدمين والمستندات (قبول/رفض/حظر)، مراجعة إثباتات الدفع، الطلبات، تعديل سعر طلب، طلبات السحب، **النزاعات** (رد كامل / تحويل كامل / تقسيم بنسبة)، **التسعير والعمولة والقواعد**، القائمة السوداء |
| الدفع والشات | **دفع مقدم (ركاب دايماً، بضاعة باختيارك) بـ Escrow، واسترجاع لو ماحدش قبل الطلب (يدوي أو تلقائي بعد الميعاد)، وشات داخل الطلب** |
| الأمان | Escrow بمعاملات ذرّية، حد إلغاءات وتجميد تلقائي، منع تكرار الموبايل/الرقم القومي، قائمة سوداء، إخفاء البيانات الحساسة حسب الدور على السيرفر، حد 10 طلبات مفتوحة، حد رفع الصور، **تحقق بخطوتين للأدمن (TOTP) + سجل دخول + حدّ مركزي للطلبات + سجل عمليات الأدمن + المراقبة/الأخطاء** |
| SEO | Schema.org، `llms.txt`، `robots.txt`، `sitemap.xml`، صفحة رئيسية ثابتة، صفحات الخصوصية/الشروط، صفحات عامة للسواقين/المستخدمين (بتفعيل أدمن) |

**منفّذ حديثاً:** تغيير كلمة السر، سجل الدخول، التحقق بخطوتين للأدمن (TOTP)، حدّ مركزي للطلبات، نسخة احتياطية JSON يدوية من لوحة الأدمن، فحص دخان E2E في CI.

**مؤجّل (مش موجود):** المدونة، بوابة الدفع (Kashier/Fawry)، تحرير تلقائي بعد مهلة (يحتاج Cron Trigger)، تطبيق موبايل أصلي، نسخ احتياطي تلقائي (يحتاج خطة Blaze)، App Check، Durable Objects.

## الخدمات
- **شحن بضاعة:** أثاث، أجهزة، بضاعة تجارية، مواد بناء، مواد غذائية… بصور إجبارية للحمولة وعند الاستلام والتسليم.
- **توصيل للمنازل:** فئة «طرود وتوصيل للمنازل» بحجم صغير (تناسب سواقين السيارات والميكروباصات). *(الفئة موجودة تلقائياً في التثبيتات الجديدة؛ لو نشرت قبل كده أضفها من لوحة الأدمن ← التسعير ← فئات الحمولة، مفتاح `parcel`.)*
- **نقل ركاب (حجز عربية كاملة):** أفراد أو مجموعات (سيارة 4، فان 7، ميكروباص 14، ميني باص 28). التسعير: سعر الكيلومتر × المسافة × معامل فئة العربية (بحد أدنى). مفيش صور بضاعة، وصورة الركوب/الوصول اختيارية، وفحص GPS شغال، والدفع والـ Escrow والعمولة زي البضاعة، وزر التأكيد «وصلت وجهتي». الإشعار بيوصل بس لسواقين عربياتهم تناسب الفئة، **والسيرفر بيمنع** أي سواق بضاعة (ربع نقل/نقل) من قبول رحلة ركاب.
  - **مقفولة افتراضياً** ويفعّلها الأدمن من التسعير والإعدادات. **تنبيه قانوني:** نقل الأفراد له تراخيص وتنظيمات مختلفة عن نقل البضائع في مصر (تصاريح تشغيل، وتأمين، وشروط للسواقين)؛ راجع الجهة المختصة/مستشار قانوني قبل ما تفتحها للجمهور.
  - **قيد عملي:** تأكيد الدفع يدوي (الأدمن يراجع التحويل)، فالخدمة مناسبة للحجز المسبق مش للمشاوير الفورية لحد ما تتضاف بوابة دفع.
- **مش موجود:** عمال التحميل/الأدوار/الأسانسير (قرارك)، ومقعد في رحلة مشتركة، وتطبيق أصلي (القرار: ويب مجاني).

## التسعير: سعر اقتراحي + عروض السواقين
- الموقع بيحسب **سعر اقتراحي** (المسافة × معامل النوع × معامل الحجم، بحد أدنى) ويظهر للعميل قبل الطلب.
- **السواق** له اختياران على أي طلب مفتوح: **يقبل بالسعر المقترح فوراً** (أول واحد يكسب)، أو **يقترح سعر مختلف** (ضمن حدود يحددها الأدمن: افتراضياً 70%–200% من السعر المقترح، ولا يقل عن الحد الأدنى).
- **العميل** يقدر يختار وقت الطلب «أستقبل عروض أسعار بدل القبول الفوري». العروض بتظهر له مرتبة بالأرخص مع اسم السواق وتقييمه ونوع عربيته، ويقبل الأنسب (رقم السواق بيظهر بعد القبول). قبول عرض بيثبّت السعر الجديد، والعمولة بتتحسب عليه.
- قبول سواق فوري بيرفض باقي العروض، وإلغاء الطلب بيرفضهم كلهم. تشغيل/إيقاف العروض والحدود من إعدادات الأدمن.

## نظام ثقة السواقين (مستويات + شارات)
بيتحسب تلقائياً على السيرفر (`functions/_lib/trust.js`) من الرحلات المكتملة ومتوسط التقييم ونسبة الإلغاء، والشروط لازم تتحقق **كلها مع بعض**:

| المستوى | رحلات | عدد التقييمات | متوسط التقييم | أقصى نسبة إلغاء |
|---|---|---|---|---|
| سواق جديد | — | — | — | — |
| موثوق | 5 | 3 | 4.0 | 15% |
| محترف | 25 | 10 | 4.5 | 5% |
| نخبة | 100 | 20 | 4.7 | 3% |

**الشارات:** «هوية موثّقة» (الأدمن راجع البطاقة والرخصة والاستمارة)، «موبايل موثّق»، «الأعلى تقييماً» (4.8+ من 20 تقييم)، «ملتزم» (15 رحلة بدون إلغاء).
**بتظهر فين:** العميل يشوفها على كل عرض سعر وعلى سواق طلبه، والسواق يشوف مستواه وتقدّمه للمستوى الجاي في لوحته، والأدمن في قائمة المستخدمين. الحدود ثابتة في الكود دلوقتي (سطور قليلة في `trust.js`) وممكن نحوّلها لإعدادات في لوحة الأدمن.

**المزايا الفعلية للمستويات العليا (كلها من الإعدادات أو الكود):**
- **عمولة أقل:** خصم نقاط مئوية من عمولة الموقع حسب المستوى — افتراضياً موثوق 1، محترف 2، نخبة 3 (عمولة 12% تبقى 11/10/9). قابل للتعديل من لوحة الأدمن. عمولة السواق الجديد المخفضة لسه بتنطبق (الأقل بينهم). السواق يشوف عمولته الحالية في لوحته.
- **أولوية في الإشعارات:** ترتيب السواقين لإشعار الطلب الجديد بيبقى بالأقرب مع «تقريب افتراضي» للمستويات العليا (موثوق 2 كم، محترف 4، نخبة 6). يعني سواق نخبة على بُعد 4.6 كم بيتقدّم على سواق جديد على بُعد 0.7 كم لو عدد المستلمين محدود. (ثابتة في `push.js`.)
- **ترتيب أحسن في العروض:** العميل يقدر يرتّب عروض الأسعار «الأرخص أولاً» (المستوى الأعلى بيكسب عند تساوي السعر) أو «الأعلى ثقة أولاً».

## توجيه الإشعارات (زي أوبر)
لما عميل ينشئ طلب: السيرفر بيختار من السواقين **«المتاحين»** اللي عربيتهم تشيل الحمولة (ربع نقل/فان = صغير، نص نقل = صغير ومتوسط، نقل ثقيل = الكل) وفي **نطاق** (افتراضي 25 كم من نقطة الاستلام حسب آخر موقع معروف)، ويبعت للأقرب **10** كحد أقصى (قابلة للتعديل). الباقي بيشوفوا الطلب في قائمة المتاح. حالة «متاح» بتنتهي تلقائياً بعد 12 ساعة بدون تحديث.

## الدفع المقدم والاسترجاع (على المنصة)
- **رحلات الركاب دايماً دفع مقدم. البضاعة بتختار:** خانة «ادفع مقدماً» وقت الطلب (والدفع بعد قبول السواق لسه متاح لو ما اخترتهاش).
- **المسار المقدّم:** العميل ينشئ الطلب ← **يدفع** (InstaPay + إثبات) ← الأدمن يأكد ← الطلب **يظهر للسواقين كطلب مؤكد** والمبلغ محجوز (Escrow) ← أول سواق يقبل **يبدأ فوراً** (مفيش دفع بعد القبول) ← تنفيذ ← «وصلت شحنتي/وجهتي» ← تتخصم العمولة والباقي لمحفظة السواق.
- **السعر ثابت** في المدفوع مقدماً (مفيش عروض أسعار)، لأن المبلغ اتدفع بالفعل.
- **لو محدش قبل الطلب** العميل يسترجع فلوسه بطريقتين: يضغط **«إلغاء واسترجاع المبلغ»** في أي وقت قبل القبول، أو **الطلب بيتلغي تلقائياً** بعد ميعاده + مهلة (افتراضي 30 دقيقة، من الإعدادات) ويتسجّل استرجاع.
- **الاسترجاع يدوي:** بيظهر للأدمن في تاب **«الاسترجاع»** (بشارة عدد)، يحوّل المبلغ على InstaPay ويضغط «تم التحويل»، والعميل بيتبلّغ. الطلب بعد القبول مفيهوش استرجاع تلقائي — بيتحل بالنزاع.
- **انتهاء الطلبات بدون Cron:** الفحص بيتم عند أول قراءة (فتح الطلب أو قوائم الطلبات، بحد أقصى كل 30 ثانية)، فلو المنصة ساكتة تماماً بيتأخر لحد أول نشاط. لو عايز دقة أعلى نضيف Worker منفصل بجدول زمني (Cron) لاحقاً.
- **بوابة الدفع الإلكتروني:** مفيش كيان قانوني حالياً فهي مؤجّلة. لما تتفعّل بتتضاف كـ «تأكيد دفع تلقائي» بنقطة استقبال إشعارات (Webhook) بتتحقق من التوقيع وتشغّل نفس منطق تأكيد الدفع، بدون إعادة كتابة. **قانونياً:** استقبال أموال العملاء على حساب شخصي (InstaPay) وردّها/تحويلها ممكن يترتب عليه التزامات ضريبية وتنظيمية؛ استشر محاسب/محامي قبل ما الحجم يكبر.

## إلغاء العميل بعد قبول السواق + اعتذار السواق
- **العميل** يقدر يلغي طلب **مدفوع وسواق قبله** طالما السواق ما استلمش الشحنة/الركاب. المبلغ المحجوز بيتقسم: **نسبة تعويض للسواق** + **نسبة للمنصة** + **الباقي يرجع للعميل** (استرجاع يدوي زي ما فوق). قبل التأكيد بيشوف الأرقام بالجنيه.
- **النسب يحددها الأدمن** (التسعير والإعدادات ← رسوم إلغاء العميل)، ولها مرحلتين: *السواق قبل ولسه ما بدأش* (افتراضي 10% سواق + 5% منصة)، و*السواق في الطريق* (افتراضي 30% + 10%). مجموع كل مرحلة ≤ 100%. رسوم الإلغاء بتدخل إيراد وعمولات المنصة في الإحصائيات، وتعويض السواق بينزل في محفظته فوراً.
- **بعد الاستلام** الإلغاء ممنوع ويتحل بالنزاع. **قبل قبول السواق** أو **قبل الدفع** بدون رسوم (وفي المدفوع مقدماً: استرجاع كامل).
- **السواق يقدر يعتذر** عن طلب قبله (قبل الاستلام): الطلب **بيرجع مفتوح لسواقين تانيين** والمبلغ لسه محجوز (سعر ثابت)، والعميل بيتبلّغ ويتوزّع الطلب من جديد، وبيتحسب على السواق إلغاء (وحسابه بيتجمّد تلقائياً لو وصل للحد).

## الأمان: بلاغات وزر طوارئ
- **بلاغ:** أي طرف (عميل/سواق) يبلّغ عن الطرف التاني من صفحة الطلب أو من الشات («إبلاغ عن المحادثة»): سلوك مسيء، تحرّش، قيادة غير آمنة، احتيال، عدم حضور… البلاغ بيوصل للأدمن ومعاه **لقطة من آخر 30 رسالة** كدليل، وفي تاب **«البلاغات والطوارئ»** يقدر الأدمن يحسمه أو يتجاهله أو يعلّق/يحظر الطرف المُبلَّغ عنه. حد 5 بلاغات في الساعة لكل مستخدم.
- **زر الطوارئ (رحلات الركاب فقط، أثناء التنفيذ):** بيفتح نافذة بأرقام **الشرطة 122** و**الإسعاف 123** (اتصال مباشر) وزر «بلّغ الإدارة بموقعي» بيبعت موقعه فوراً. الأدمن بيوصله **إشعار Push عاجل** وبيظهر في أول التاب بشارة حمراء، ومعاه موقع الضاغط وأرقام العميل والسواق ومسار الرحلة. الضغطات المتكررة بتحدّث الموقع بس، وحد 3 استغاثات في الساعة.
- **تنبيه:** ده مش بديل عن الجهات المختصة. مفيش من يراقب لوحة الأدمن 24 ساعة؟ ركّز الرسالة للمستخدم على الاتصال بـ 122/123 أولاً.

## الشات بين العميل والسواق
شات نصي داخل صفحة الطلب، بيفتح **بعد ما سواق يتحدد** ولحد اكتمال الطلب (ويفضل شغال أثناء النزاع)، وبعدها السجل للقراءة بس. الطرفين بيتبلّغوا بإشعار Push بكل رسالة. حد أقصى 500 حرف للرسالة و20 رسالة في الدقيقة. **الأدمن يقدر يقرا المحادثة** (كدليل، وبتظهر تلقائياً في بطاقة النزاع) لكن مايبعتش. التحديث بيتم دورياً والصفحة مفتوحة (ده بيزوّد استهلاك القراءات — شوف حدود الخطة المجانية).


## الحدود المجانية (راجع لوحة Firebase / Cloudflare — الأرقام بتتغيّر)
- **Firestore (خطة Spark):** شوف «حدود الخطة المجانية» فوق (50 ألف قراءة / 20 ألف كتابة يومياً، 1GiB تخزين). الصور مخزّنة كمستندات (~60-120KB للصورة بعد الضغط) فالتخزين بيشيل تقريباً آلاف الصور.
- **Cloudflare Pages Functions:** 100 ألف طلب/يوم على الخطة المجانية (طلبات الـ API). الصفحات بتعمل Polling بفواصل مضروبة ×`POLL_SCALE` (افتراضي 3).
- **OTP بالـ SMS:** Firebase Phone Auth بيتحاسب لكل رسالة على Blaze. الافتراضي `phoneOTP: false` (مراجعة الأدمن للبطاقة).
- **OSM/Nominatim/OSRM العامة:** مجانية بسياسة استخدام عادل، للإطلاق التجريبي.

## اللي اتختبر واللي لسه لأ
**اتختبر (`npm test`، 616 حالة سيرفر + اختبارات الواجهة):** السيرفر فوق **Firestore وهمي (`test/fake-firestore.mjs`)** بيحاكي واجهة REST الحقيقية (commit ذرّي بشروط، batchGet، runQuery، تجميع، increment) **وبيرفض أي استعلام محتاج فهرس مركّب**: التسجيل ومنع التكرار، السعر، **قبول متزامن (واحد بس ينجح)**، الدفع والتأكيد، GPS والصورة، تحرير الـ Escrow والعمولة، **سحب متزامن بكامل الرصيد (واحد بس ينجح)**، النزاعات، التجميد التلقائي، القائمة السوداء، الإحصائيات، الصلاحيات وإخفاء البيانات الحساسة، صلاحيات الملفات، `/api/health`، **عروض الأسعار، الدفع المقدم والاسترجاع والانتهاء التلقائي (بدون تكرار عند التنافس)، والشات، وخدمة الركاب ومزايا المستويات، توجيه الإشعارات لأقرب السواقين، وتنضيف الأجهزة الميتة (بـ FCM وهمي)،** ومنطق الـ Polling وحماية XSS والترجمة.

**لم يُختبر (ولازم تجرّبه بنفسك قبل أي مستخدم حقيقي):** **Firestore الحقيقي** (الاختبارات على نسخة وهمية مبنية على فهمنا لواجهة REST — أي اختلاف بسيط في سلوك الخدمة الحقيقية ممكن يظهر هنا أول مرة)، توقيع توكن حساب الخدمة مع Google فعلياً، الإرسال الفعلي عبر FCM ووصول الإشعار لجهاز حقيقي، الواجهة داخل متصفح حقيقي، وCloudflare Pages الفعلي، وFirebase Auth الحي. اتبع الخطوات 4 و5 و8 ثم «قائمة التجربة» على مشروع تجريبي.

## حدود معروفة
- التحديث بيوصل خلال حوالي 12-40 ثانية على الإعداد الافتراضي ×2 (Polling؛ 6-20 ثانية لو `POLL_SCALE = 1`)؛ الإشعارات هي اللي بتوصل فوراً.
- **الموقع المباشر وحالة «متاح» بتتحدّث والصفحة مفتوحة** (المتصفح مابيسمحش بتتبع الموقع في الخلفية). تجربة أوبر الكاملة (تتبع بالخلفية، شاشة الطلب فوق القفل) محتاجة **تطبيق أصلي** — ممكن نلفّ نفس الموقع بتطبيق (Capacitor) لاحقاً.
- الإشعارات مش مضمونة 100% (بتعتمد على المتصفح والجهاز وتوفير الطاقة).
- فحص GPS بيمنع الخطأ لكن مش تزوير موقع متعمّد؛ الصور وسجل الإحداثيات أدلة للأدمن.
- الدفع ورد المبالغ يدويين (InstaPay)، ومفيش تحرير تلقائي لو العميل ما أكدش.
- حذف الصور القديمة مش مؤتمت — راقب حجم Firestore في لوحة Firebase.
- **قانونياً:** احتفاظ المنصة بأموال العملاء (Escrow) قد يخضع لتنظيمات الدفع والتراخيص في مصر. استشر مستشاراً قانونياً قبل الإطلاق التجاري، وجهّز الشروط وسياسة الخصوصية (البطاقات الشخصية بيانات حساسة).
